# 截屏快传

在手机和 Mac 或 Windows 之间通过局域网传文件。手机可以选择相册图片上传，也可以扫描电脑的下载码接收文件。电脑端按接收日期和文件类型保存上传的文件。

## 电脑端

[下载 Mac 和 Windows 接收器](https://github.com/hanbing-charger/screenrelay/releases/tag/v0.9.0)

1. 解压与电脑对应的接收器包。Apple 芯片 Mac 选 macOS-arm64，Intel Mac 选 macOS-x64。常见 Windows 电脑选 Windows-x64，ARM 版 Windows 选 Windows-arm64。
2. Mac 双击「启动截屏快传.command」，Windows 双击「ScreenRelay.exe」。如果防火墙询问，允许在私人网络接收。构建未做商业签名或 Apple 公证，首次启动时系统可能要求在安全设置里确认来源。
3. 浏览器会打开电脑控制台。点 **扫码配对**，让手机端扫描二维码。若显示多个地址，选手机所在 Wi-Fi 对应的网卡地址。电脑端的已配对设备列表按手机的应用配对标识显示。手机重装后若产生新标识，可以从列表移除旧配对。
4. 在控制台的 **保存位置** 点 **修改保存位置**，选择文件夹或输入完整路径，再点 **保存**。默认目录是用户目录下的 `ScreenRelay`。接收器会记住新目录，之后收到的文件按日期和类型保存到那里。此前收到的文件可在控制台查看。
5. 要给手动上传的图片指定目录，在 **图片保存位置** 点 **修改图片保存位置**，选择文件夹或输入完整路径，然后保存。新收到的图片会保存在所选目录的 `日期/photo` 下，也可以恢复为跟随通用保存位置。
6. 保持接收器窗口运行。按 `Ctrl+C` 或关闭窗口可停止接收。

## 手机端

[下载 Android APK、iOS IPA 和鸿蒙 HAP](https://github.com/hanbing-charger/screenrelay/releases/tag/v0.9.0)

手机和电脑连同一个 Wi-Fi。在 Android、iOS 或 HarmonyOS NEXT 端点 **扫码配对**，扫描电脑面板上的二维码。二维码有效期内可给多台手机使用，同一次安装重复扫码会更新同一个配对。也可以手动填写地址和配对码，再点 **保存配对**。配对后即可选择图片或诊断日志上传。

| 手机系统 | 使用方式 |
| --- | --- |
| Android 10 及以上 | 安装 APK，用系统文件选择器选图，可多选。 |
| iOS 13 及以上 | 用 Xcode 打开 iOS 工程并签名安装。按系统提示允许访问局域网。iOS 13 支持单选，iOS 14 及以上支持多选。 |
| HarmonyOS NEXT | 用 DevEco Studio 构建并签名安装。在系统相册选择图片或录屏。支持 Android APK 的早期鸿蒙机型可使用 Android 端。 |

各平台的构建和权限细节见源码中的 [Android](android)、[iOS](ios) 和 [HarmonyOS](harmonyos) 目录。

## 手动上传图片

手机和电脑使用 v0.7.0 或更新版本并配对后，在手机首页点「选择图片上传」，在系统选择器选择要发送的图片。鸿蒙端选好后，点「发送所选的文件」。电脑的「最近接收」会标注「图片」。v0.8.0 起可单独配置 **图片保存位置**，收到的图片会写入该目录的 `日期/photo`，默认使用通用接收目录。

系统选择器授予对所选图片的读取权限。电脑支持 JPEG、PNG、HEIC、WebP、GIF、AVIF、TIFF、DNG 等格式。

## 从电脑发送文件

1. 手机和电脑连同一个 Wi-Fi。打开电脑接收面板的 **文件下载码**，点 **选择文件**，或输入完整文件路径。
2. 选择手机所在局域网的接收地址，再点 **生成二维码**。下载码在 30 分钟内有效。
3. 在手机的截屏快传中点 **扫码接收文件**，扫描电脑显示的下载码。下载完成后，文件会自动保存。

| 手机系统 | 文件位置 |
| --- | --- |
| Android | 系统「下载」目录的顶层 |
| iOS | 「文件 → 我的 iPhone → 截屏快传」目录的顶层 |
| HarmonyOS NEXT | 应用的接收文件目录，可用应用里的导出入口保存到系统位置 |

电脑面板的 **扫码配对** 用来添加手机。**文件下载码** 用来下载所选文件。下载支持断线后接着传，原文件应在下载完成前保留在电脑上。

## 上传手机诊断日志

在手机端打开 **诊断日志**，查看截屏快传最近 24 小时内可用的崩溃和无响应记录。应用将每条记录生成独立的 TXT。勾选一份或多份，在页面里点上传。升级电脑接收端至 v0.6.0 后，可以在接收列表里查看「诊断日志」，原文件保存在当前接收目录的 `日期/diagnostic` 下。

| 手机系统 | 可用记录 |
| --- | --- |
| Android | Android 11 及以上读取系统保留的崩溃和 ANR 退出记录。Android 10 可记录本应用的 Java 崩溃。 |
| iOS | iOS 14 及以上读取 MetricKit 交付的崩溃和卡死报告，系统可能延迟交付。 |
| HarmonyOS NEXT | 读取系统交付的应用崩溃和应用冻结记录。 |

诊断 TXT 仅在用户选中并点击上传后发送。

## 连接与保存

- 手机和电脑需要能在局域网内互相访问。访客 Wi-Fi 可能隔离设备，电脑地址变动后需更新手机配置。
- 手机端直连已配对的接收地址。系统配置了 Charles 普通 HTTP 代理时，局域网上传仍走直连。传输速度取决于 Wi-Fi 和电脑写盘速度。
- 默认接收端口是 TCP 8765，传输为局域网 HTTP。请在可信 Wi-Fi 中使用。若启用 HTTPS，手机需信任证书，填写的主机名或 IP 需与证书匹配。控制台独立监听在电脑本机。
- 默认最大单文件为 2 GiB。电脑端可用下面的参数指定本次启动的保存目录、端口和限制，一次只运行一个接收器实例。

```text
ScreenRelay -folder "/path/to/captures" -listen 0.0.0.0:8765 -max-mib 4096
ScreenRelay -tls-cert fullchain.pem -tls-key privkey.pem
```

## 从源码构建

电脑端使用 Go 1.24 及以上版本。Go 会在构建时下载二维码依赖。在 `desktop` 目录运行：

```sh
go test ./...
go build -o ScreenRelay .
```

Windows 使用 `go build -o ScreenRelay.exe .`。手机工程需用各平台工具链编译并签名。接收接口约定见 [desktop/PROTOCOL.md](desktop/PROTOCOL.md)。
